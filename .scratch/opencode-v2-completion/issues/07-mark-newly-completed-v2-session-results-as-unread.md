- Decisions: follow the pinned [V2 Session.Info markers](https://github.com/anomalyco/opencode/blob/v2.0.23/packages/schema/src/session.ts) and [session.view operation](https://github.com/anomalyco/opencode/blob/v2.0.23/packages/protocol/src/groups/session.ts). A valid positive idle marker is unread when viewed is absent, malformed, or older; updated time and outcome labels do not determine attention. Active rows keep their working indicator. V1 rows and mutations retain their previous behavior.
- **S1 / viewing decision:** acknowledge each newer completion displayed by the synchronized, visible, foreground chat. `ChatClient` keeps one request in flight and then sends the latest still-unread displayed marker; intermediate markers can coalesce. The acceptance criterion means an older request cannot acknowledge an unseen newer completion: it remains unread until separately displayed and acknowledged, without requiring another visit. The hosted test holds idle 2000, displays idle 3000 and expects POST bodies for both, then verifies idle 4000 during the same visit; service coverage verifies coalescing and maximum concurrency of one. Background synchronization and list selection alone do not acknowledge results.
- **S2 / recovery decision:** the service owns acknowledgement tasks independently of transcript re-sync. Hosted tests hold both the POST and canonical reread, trigger re-sync, then confirm success without a dropped attempt. Disappear, background and session switch end display observation and cancel its task. Always reread canonical state after the mutation, even if its response was lost. Only server-provided viewed markers confirm success; merge only that marker, preserving newer idle/outcome/metadata. An unconfirmed mutation or failed reread exposes Try Again. Typed `ResultViewingState.failed` retains the retry route even when an unrelated operation changes `errorMessage`; confirmed retry or later canonical confirmation clears it.
- **S3 / sidebar decision:** observable `SessionsService` publishes confirmed viewed markers scoped to the connected client. The list immediately merges them into matching rows with `withViewedMarker`, including after a poll captured before confirmation. The boundary test proves immediate badge removal, unchanged unrelated rows/outcomes, protection from stale polls and preservation of unread status for a newer idle marker. The iPad sidebar uses this same list wiring.
- **S4 / periodic refresh decision:** every 30 seconds while the foreground V2 list is visible, reread only unread, inactive rows. Four is the maximum number of concurrent canonical reads, not a total request cap. The transport test has 200 read rows, two unread inactive rows and one unread active row and asserts exactly two session reads. A failed attention read preserves outcome and attention state and does not enter the two-second outcome retry queue. Appearance/foreground and ended/opened-session outcome recovery retain ticket 06 behavior.
- **S5 / desktop event decision:** native `session.viewed` events recover session info and merge only its canonical viewed marker; they do not reconcile transcript, inbox, permissions or forms. Matching/other-session tests assert the exact request paths, unchanged history/title and retained synchronization. Coalesced marker reads also publish confirmation to the list.
- **Standards corrections:** acknowledgement policy moved from `ChatView` into observable `ChatClient`; the view only reports synchronized display/foreground evidence and forwards retry. Error state is typed rather than inferred from message prefixes. Shared `OCSession.completedResultMarker`, `hasViewedResult(at:)` and `hasUnreadResult` helpers centralize validity/coverage decisions. Hosted negative checks no longer sleep a fixed 100 ms: tests wait for explicit lifecycle, held-request, synchronization or confirmed-marker signals and assert settled request sequences/concurrency. No ViewModel/Presenter or navigation change was introduced.
