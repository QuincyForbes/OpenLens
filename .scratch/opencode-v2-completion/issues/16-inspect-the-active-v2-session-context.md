**Review corrections (2026-10-09):**

- **Spec finding 1 — failed chat synchronization:** context reads no longer depend on stream synchronization or workspace-rebind readiness. The endpoint reads the selected session's authoritative projection directly; scope/revision checks still reject superseded responses. Missing selection/service is a failure, not unsupported context. `failedChatSynchronizationDoesNotBlockContextReadOrRetry` first causes a real production chat sync to fail, then proves a context failure is surfaced and retry succeeds while `isStreamSynchronized` remains false. The unavailable screen now refers only to protocol/endpoint support, with no misleading wait-for-sync message.
- **Spec finding 2 — client-only cancellation:** `ChatClient.loadActiveContext` converts a `CancellationError` into the retryable “Context changed while it was loading. Try again.” error when neither its task nor selected-session scope was superseded. The sheet's existing failure state replaces the spinner and exposes Try Again. Real task/scope cancellation remains silent. Both held `binding` cases now assert the scope stayed unchanged, the invalidated success/error became that actionable failure, and a subsequent read succeeded. Decision: report one explicit retryable failure instead of silently retrying and potentially repeating a changing binding indefinitely.
- **Spec finding 3 — occupancy documentation/product decision:** the implementation **removed the existing V2 percentage ring**, replacing it with the Context button and explicit unknown occupancy in the inspector. The old ring used the latest retained assistant reply's usage, not a cumulative session total. The gap analysis permits last-request usage plus an applicable model limit as an indicator. Decision for this unattended run: keep the ring removed because the existing reply usage has no freshness check tying it to the current projection after desktop context/model changes or compaction. Choosing unknown follows this ticket's insufficient-data criterion without claiming every last-request estimate is invalid. V1's existing ring is preserved. `ENABLED.md` is corrected to describe the removal explicitly.
- **Spec finding 4 — held-read control:** the parameterized test now includes no-change success and server-failure controls. The successful control proves a suspended request returns the actual ordered projection after release; the failure control preserves the server error. These two controls complement sixteen genuine task/scope-invalidated cases and the two retryable internal-binding cases.
- **Standards finding — duplicated projection/conversion:** moved V2 projection and stable-ID replacement into `OCTranscriptEntry.projectV2`, shared by active context, paged history and the context/subagent screenshot fixtures. `MessagesService.transcript(from:)` centralizes conversion into the presentation transcript. `activeContextAndHistoryKeepUniqueIDsInOriginalOrderWithLatestValues` covers both read endpoints with duplicate chat and context IDs plus an unknown entry: each ID appears once at its original position, with its latest content. This fixes the active-context `ForEach` identity risk while retaining history's existing overlap behavior.
