Unanswered omits the value and leaves both `eq false` and `neq true` branches inactive; No submits false and activates their required branch. Returning to Not answered hides the branch and strips its stale draft. Applied to every optional Boolean without a default so displayed state and submitted answers agree even without dependents; existing defaulted/required Boolean switches retain their behavior. Such forms now recover with an explicit unsupported state and cannot reach reply transport through either service. Added the hidden earlier Boolean with a false default to `unsupportedPredicatesRecoverExplicitlyAndCannotReachTransport`; it reproduced accepted rules/unsafe reply admission in `build/afk-logs/20261009-202048-tests-1.log` before the guard. Decision: preserve existing static hidden-field omission and reject dependent rules rather than infer default submission semantics.
- **Review finding 3 — external contract reason:** retained the conditional-external restriction using the review's allowed documented-contract alternative. In the pinned [ExternalField schema](https://github.com/anomalyco/opencode/blob/v2.0.23/packages/schema/src/form.ts#L100-L107), external fields do **not** include `FieldBase`, `hidden`, `required`, or `when`; they contain only key/type/url/title/description. The pinned [server validateAnswer](https://github.com/anomalyco/opencode/blob/v2.0.23/packages/core/src/form.ts#L240-L246) requires an external value of true and continues **before** calling `isActive`. Therefore omitting acknowledgement for an allegedly inactive external field would contradict this contract; local activity evaluation alone does not make that reply safe. Added a code comment at the restriction and the parameterized `conditionalExternalFieldsCannotGuessServerAcknowledgementSemantics` service/transport test. For both controlling answers and with/without an acknowledgement, Chat and Inbox expose unsupported state and issue no POST. Ordinary external-field acknowledgement coverage remains passing. Predicates referencing an external acknowledgement remain unsupported separately, as the server's creation validation excludes external targets.
- **Review finding 4 — hosted test reliability:** replaced every fixed UI settling sleep in the original hosted test with the same bounded condition polling used by the new hosted regression: poll every 10 ms for at most 5 seconds, checking controls, displayed draft text, branch removal, and Submit availability/callback delivery. No 150/300 ms settling sleeps remain. The new test uses a scene-attached presented sheet and public `UINavigationItem.trailingItemGroups` actions to match the simulator's actual toolbar. Early harness runs assumed a UIButton or legacy `rightBarButtonItem`; those assumptions and a Swift Testing macro expansion limitation were corrected before final verification. No production hooks or private API selectors were introduced.
