- **Decisions — supported operation and admission:** followed the pinned [V2 compaction endpoint](https://github.com/anomalyco/opencode/blob/v2.0.23/packages/protocol/src/groups/session.ts#L485): POST `/api/session/{sessionID}/compact` with a caller-provided `msg_` ID and explicit `delivery: steer`, using the session's own location without a workspace-picker override. This schedules compaction at the next step boundary; admission never means completion. A 2xx response remains admitted even if its body is unreadable: retain the caller ID as an accepted control while canonical inbox/history recovery supplies its lifecycle. A lost response is reconciled first. An explicit unresolved-admission retry reuses the same ID, and recovery withdraws it if the request has appeared in the inbox or timeline. No automatic retry submits compaction. A deliberate new request after a terminal result gets a new ID.
- **Decisions — state ownership and restoration:** admission state belongs to the existing observable `ChatClient`, scoped by session and client identity, so closing or reopening the sheet cannot reset it. The existing durable inbox and canonical timeline restore work from other clients and after app-state reset/reconnect; reads and reopenings never POST. Admission is enabled only after shared-inbox/history synchronization, avoiding new work while recovery is incomplete. Canonical compaction events already trigger history recovery; its active-context revision reloads the open inspector. Explicit Refresh/pull-to-refresh now also recovers operation status, then reads active context even if chat recovery failed. Context snapshots/disclosure remain view-local, the new control receives the shared service through `@Environment`, and completed summaries initially expand for inspection. V1 routes, historical usage and navigation ownership are unchanged; no ViewModel/Presenter layer was added.
- **Decisions — failure, interruption and support:** retain raw server compaction status separately from presentation text. Completed, running and failed states come from the canonical compaction record, preserving the error reason. Associate an interrupted execution only when an authoritative interrupted idle marker immediately follows the failed compaction in timeline order; a later turn's interruption cannot relabel an older failure. The UI says **Execution interrupted**, preserving both the failed control and idle record without inventing successful compaction. Unknown statuses remain unconfirmed with no active retry unless this client retains an uncertain admission identity. V2 info does not advertise per-endpoint support: use negotiated V2 evidence initially, then treat bare HTTP 404/405/501 as unavailable and remember that result for the current connection across session switches. Structured session errors, auth/provider/network errors remain distinct from unsupported support. No server-version threshold or legacy summarize fallback was introduced.
