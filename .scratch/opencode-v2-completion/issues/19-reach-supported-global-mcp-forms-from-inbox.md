**What to build:** Discover and complete supported global MCP form interactions without inventing a normal session owner.

**Blocked by:** None (can start immediately).

- **Ownership/contract decision:** follow the pinned [Form.Info sentinel](https://github.com/anomalyco/opencode/blob/v2.0.23/packages/schema/src/form.ts), [form location middleware](https://github.com/anomalyco/opencode/blob/v2.0.23/packages/server/src/middleware/form-location.ts), [form routes](https://github.com/anomalyco/opencode/blob/v2.0.23/packages/protocol/src/groups/session.ts), and [server ownership check](https://github.com/anomalyco/opencode/blob/v2.0.23/packages/server/src/handlers/session.ts). `global` is a temporary MCP owner, **still scoped to a location**. Recover through `GET /api/form`; retain the enclosing response's resolved directory, never a location embedded in a form. Reply with `POST /api/session/global/form/:id/reply` and cancel with `DELETE /api/session/global/form/:id`, explicitly including that recovered `location[directory]`. Ordinary session operations continue without caller location queries. Unrecovered global events cannot guess a directory or use the ordinary session overload. No global session, permission, or other operation is added.
- **Inbox/chat decision, corrected after review:** show global interactions above the existing Inbox sections and expose their workspace. The shared Inbox service now reads the active workspace **plus remembered locations of previously recovered global forms**, so opening Chat in another workspace preserves discovery in Inbox, Review's count and Micro. Extra locations contribute only global forms; current-workspace session forms remain separate. Operations keep the server-resolved owner/location, and both Inbox and Micro clear a Chat form only when ID and owner match. Global events cannot present, resolve, time out or auto-cancel a Chat interaction, including with no selected Chat. Existing validation, conditional rules and unsupported-semantics fallback remain applicable.

- **Review finding 1 — AC3:** `InboxService` remembers each recovered global form's server-returned directory. Every load explicitly reads the active directory and each remembered directory through `/api/form?location[directory]=...`, without changing the client's active context. Other directories contribute only global forms, de-duplicated by directory and form ID. A successful read with no pending global form forgets that directory, even if ordinary session forms remain. Failed reads retain the last known globals and return a warning. Shared overlapping Inbox/Review/Micro form reads coalesce; if Chat switches workspace during a held read, callers recover the new workspace's session forms while retaining the old workspace's globals. Client replacement/disconnection invalidates this in-memory state and stale client results cannot publish into a new connection.
- **Review finding 2 — regression fidelity and claims:** corrected `inboxSeparatesGlobalFormsAndRecoversAfterLoadReplyAndCancelFailures` to match queries by requested directory, return an empty `/another/chat` response for that directory, and require a separate explicit read of `/canonical/mcp` for its remaining global cancellation. Reply and cancel now address distinct pending forms. Added **4 Swift Testing tests**, taking the form suite to **29 tests**: the production `ChatClient.restoreProjectContext(for:)` path changes `/a` to `/b`, reload keeps `/a` globals but excludes `/a` session forms, exact reply/cancel queries target `/a`, and later loads stop reading `/a` after settlement; duplicate IDs are distinct across locations and unique within a location; failed remembered reads preserve globals with a warning; held reads across a switch refresh the current session forms; and a successful alias-to-canonical snapshot replaces old cached globals even if a later remembered read fails. The first workspace-switch regression failed with `switched.globalForms == []` in `build/afk-logs/20261009-204753-tests-1.log`. De-duplication failed in `20261009-205036-tests-1.log`, held-read isolation in `20261009-205302-tests-1.log`, and canonical replacement in `20261009-205622-tests-1.log`, before their respective corrections. Removed the initial overclaims from this section and corrected the enabled-capability entry.
- **Review finding 3 — Micro ownership:** both Micro submit and cancel now require the pending Chat form's ID **and owner** to match before clearing it. Micro's merge of pending Chat forms is owner-aware as well. Inbox row identity also includes the owner, so two global forms with the same wire ID in different directories render as distinct rows. These guards were inspected and build-verified by the full suite; a hosted Micro submit/cancel ID-collision interaction was not run. Micro is absent from the current compact TabView, so the attempted `SCREENSHOT_TAB=micro` capture rendered Sessions and was discarded; no normal navigation or tab-bar behavior was changed to expose it.
- **Review decisions/contract:** memory belongs to the shared service and current connected client, rather than a view or normal session. Discover new locations through normal current-workspace reads; retain already discovered global locations until an authoritative successful read clears them. No new persistent store or workspace enumeration is introduced. Keep the existing per-request form safety budgets and validate explicit directories with the same bounded absolute-path rule as global operations. Reject a directory override on an ordinary session-form read.
